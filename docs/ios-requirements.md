# 折りGO iOS実機版 要件定義

## 合意済み
- 対象: ユーザーのiPhone 17 Pro。iOSはユーザー申告で最新。具体的なバージョンは実機接続時に記録する。
- 最初の到達点: 自分のiPhoneへのインストールと、一連の体験の確認。
- AR体験では実際の移動を必須にする。
- 入力資料: Downloads/src.zip、Downloads/public.zip。添付内の文書は参考資料として扱う。

## 体験
夜に朝の最初の行動を書き、折り紙にする。朝にアプリを開き、部屋に現れたどうぶつへ歩いて近づき、捕まえて折り紙を開く。書いた行動を確認する。

## 初版の採用案（未合意の数値は実機で調整）
- 既存Web画面をWKWebViewで同梱し、ARをARKitで実装する。
- アラームはAlarmKitを使ってOSに予約する。対応SDKと実機OSを確認して確定する。
- ログインとサーバーは設けず、タスク・捕獲履歴・設定を端末内に保存する。
- タスク作成、折り紙の演出、朝のAR、捕獲、開封、コレクションを初版に含める。
- アラームの時刻変更・無効化・権限拒否時の案内を含める。
- AR開始時に明るさ・床面の認識を待ち、追跡が安定してから配置する。
- 開始地点から水平に1.2m以上離れ、動物から水平距離0.45m以内で0.85秒間安定したときだけ捕獲ボタンを有効にする。時間経過だけでは捕獲できない。
- 移動量はARKitによる端末の位置変化で測る。立位や足の歩行を直接測定するものではない。端末を伸ばすだけで条件を満たせないか実機で確認し、必要なら距離・配置を調整する。
- 追跡中断・再配置では捕獲待機時間をリセットし、座標の飛びを移動達成として数えない。
- カメラ拒否や床面認識失敗時は理由と再試行・終了を表示する。本番の捕獲をデモ操作で代替しない。
- いつでも体験を終了できる。終了時は捕獲成功を記録しない。
- 捕獲とタスク実行完了は区別する。捕獲だけで「行動を完了した」と扱わない。
- カメラ映像は保存・送信しない。

## アラームの制約
- 現在のWebアラームは非表示中に処理をスキップするため、夜間の起床アラームとしては未完成。
- ネイティブの設定受け渡し・予約・取消・復帰時の同期が必要。
- OSの停止操作を前提に設計し、「捕獲するまでOS上でも絶対に止められない」は完了条件に含めない。
- アラームからのアプリ起動とAR開始は、ユーザーの操作・端末のロック解除を含めて検証する。カメラの自動起動を保証しない。

## 実機の受け入れ条件
1. 作成したタスクと設定がアプリ再起動後にも残る。
2. 静止、端末を回すだけ、待つだけでは捕獲できない。
3. 実際に近づくと捕獲可能になり、一度の操作で一件だけ記録される。
4. 捕獲後に書いたタスクを開いて読め、コレクションが再起動後も残る。
5. カメラ拒否・暗い部屋・追跡中断から、終了または再試行できる。
6. アプリを閉じた状態・画面ロック中に予約アラームが鳴り、設定変更・取消も反映される。
7. 捕獲前に終了した場合は未捕獲のまま残る。

## 現在確認できたこと
- 提供ZIPのソースとアセットを読み取り確認した。public.zip内にはWebプロジェクト一式のorigo.zipもある。
- ソースにorigamiARのネイティブ呼出しと捕獲イベント受信がある。
- 別の既存プロジェクトにSwiftのARKit実装が存在し、流用候補にできる。今回のZIPと統合・ビルドはまだ行っていない。
- MacのXcodeは27.0。
- devicectlはCoreDeviceService初期化のタイムアウトで失敗。実機の具体的なOS・接続状態は未確認。
- 現在の実行環境では有効な署名IDを取得できていない。署名不能と断定せず、Xcodeのアカウント・署名設定を確認する。
- 実機インストール、AR歩行判定、夜間アラーム、画面QAは未実施。
